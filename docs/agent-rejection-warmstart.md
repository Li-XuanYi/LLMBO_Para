## 具体机制

每轮直接请求最多4个新六维候选，不调用 LLM 从池中选点。校验失败时记录原参数和拒绝原因；库存不足时附上容量上界与所需电量；DFN不完整时反馈各倍率覆盖时间、所需结束时间、短缺秒数、真实截止事件及有效单倍率 RMSE/末端残差。下一轮据此修改参数。两个扩散系数与另外四个参数都是决策变量，Reference的名义值不能被当成固定值。

一旦取得8个完整有效点，立即停止生成/评价；程序用原有 RMSE与多样性规则确定缓存次序。否则达到40个返回候选或10次生成请求便停止并报告不足。非法、重复、库存拒绝的点也占40点预算；空响应、JSON/候选列表协议拒绝仍占请求预算。模型超额返回导致越过总预算时保存协议错误，禁止超额仿真。API/网络执行错误保留脱敏诊断并停止，不能靠随机点掩盖。

刚完成的24点纯提示词计划作为经过哈希、源文件、物理/数据签名和标签复核的首轮反馈。原先21个DFN候选/84次倍率求解和1次API单列，不重算、不计作新的有效起点。新评价记录全部保存；累计归因成本为旧成本加新成本。原始实测曲线不发送给API，只发送此前已获准的摘要。

反馈上下文只保留最近20条拒绝摘要，并在需要时额外保留覆盖最接近的3C候选，不重复嵌套整份历史。全部记录仍在本地保存。此前参数向量用于去重，完整有效点及其最佳RMSE摘要单独标识。程序不替Agent修改参数数值，也不放宽完整时段规则。
