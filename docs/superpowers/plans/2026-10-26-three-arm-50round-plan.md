## Stage 1 — software runner, TDD

Create `scripts/run_et_three_arm_validation.py` as the parent supervisor and `scripts/et_three_arm_validation_worker.py` as a cold native worker. Keep existing two-arm scripts intact. Reuse `llmbo_para.electrothermal_workflow.prepare_electrothermal_experiment`, `make_electrothermal_backend`, the existing `ElectrothermalLLMController.generate_warmstart`, `MOOptimizer`, the LGBO Region controller and existing deep audit/independent metric functions. Do not duplicate the optimizer, DFN evaluator, scalarization, GP or Prompt. Expose named, typed helper interfaces rather than embedding protocol logic in the legacy `Optimizer`:

1. `load_protocol(path) -> FrozenProtocol`: require exactly five unique specified seeds, three named arms, initial count eight, 50 **new** rounds, two ordered fit rates, valid three-phase cost accounting, prior source signatures and no credential field. Return immutable cost and seed plans; refuse mismatched or mutated manifests.
2. `config_for(base, *, kind, arm, seed, remaining, initial_plan) -> ElectrothermalConfig`: separate initialization, WarmStart and main modes; preserve the base physical/data/scalarization fields. BO and WarmStart-only must have `llm.enabled=false` for formal BO rounds. Full uses the existing OpenCode chat-completions endpoint/model/Region mode. Require `total_candidate_budget=8+50=58` for main.
3. `initialize_numeric(seed_plan, prepared, store, budget, backend) -> SignedInitialPlan`: truly evaluate the eight predeclared Sobol physical vectors using the existing evaluator, preserve their order and full rate curves, then issue a signed plan. A failure or fewer than eight complete distinct pairs stops; do not silently replace a point. Charge each solve before calling PyBaMM.
4. `initialize_warmstart(seed_plan, prepared, store, budget, controller, backend) -> SignedInitialPlan`: bind the existing controller to the actual evaluator and solver budget, call `generate_warmstart` with pool target 16, selection count eight, three planned requests/48 proposals/16 evaluated candidates. Require eight complete distinct selected points. Record 8–16 actual complete screening-pool size, requests, rejected/partial candidates and two-rate solve cost. The selected eight are imported, never regenerated, into both WarmStart arms of that seed. Do not relabel numerical points as WarmStart.
5. `run_arm(*, arm, seed, initial_plan, prepared, budget, controller) -> CaseEvidence`: use the actual `MOOptimizer.optimize(58)` with fixed seed and current weight scheduler/GP/EI. Reconstruct each arm in a cold source-pinned process. BO and WarmStart-only cannot instantiate a live Region transport in their BO phase; Full may issue at most 50 Region requests. Save one attempt record for each of 50 rounds and all complete/partial rate records. Audit that the two WarmStart arms have identical initial-plan digest, initial true `Y`, weight sequence and first numerical context before any Region intervention. Keep BO's separate numerical initial-plan digest visible.
6. `summarize_and_seal(protocol, cases, ledger) -> ComparisonEvidence`: independently recompute both RMSEs from archived voltage/temperature curves and fixed-space HV from true complete pairs. Report per-seed and pooled RMSE/HV, 50-round trajectories, exact Pareto parameter sets and uncertainty across five seeds. Attribute BO initialization, WarmStart screening, main rounds and API gate separately. Seal all files without credentials; fail the audit on tampered temperature curves, parameter/data/rate/weight/scales, initial-plan signatures or mismatched cost counts.

Parent supervisor owns the sole durable, hash-chained budget ledger and native process tree. Reuse tested Windows job/process supervision and API/DFN precharge acknowledgements, but instantiate **new protocol caps** rather than inheriting old 20-round caps: gate `6 API/0 DFN`; all initialization `15 API/240 DFN`; main `250 API/1500 DFN`; total `271 API/1740 DFN/28800 s`. Each nested cap is an upper bound, not an allocation to force-consume. The parent must acknowledge before a worker can make an API request or start a solve, reject duplicate/late/over-cap charges, and close owned children on stop. One rate solve = one DFN charge; one network request = one API charge even on timeout. No automatic retries. Sequential initialization plans are completed before the 15 formal arms; run formal arms in the frozen per-seed order. Transport failures and formal consecutive-failure rule use the current code paths. A complete response must be identity-bound, legal and able to pass the frozen GP/EI/tilt check before claiming Region acted.
