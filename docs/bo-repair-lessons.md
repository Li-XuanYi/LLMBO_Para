# 本轮实现与验证中发现的问题

这些记录是排错经验，不改变科研假设或用户授权范围。原始错误日志保存在 `bo-repair-work/20261012T054609Z_p0/`，后续修复使用新的日志文件，没有覆盖失败记录。

| 现象 | 原因 | 修复与后续约束 |
|---|---|---|
| 四个 GP 只保留完整四倍率候选，丢弃部分有效 RMSE | 用整候选 valid 过滤所有倍率训练数据 | `training_data=per_rate`，逐倍率选择真实有效标签；失败 RMSE/J 仍为空 |
| 覆盖不足和求解器错误只剩文字异常 | 模拟器只返回 `(t,V)`，终止元数据丢失 | 增加结构化 trace、事件和错误类型；旧记录缺失事件保持未知，不能反推为电压截止 |
| 每轮重拟合四个 GP，包括数据完全未变的 GP | 没有检查训练输入/标签/参数组指纹 | 缓存模型，仅重拟合改变的数据集，同时保留每轮状态快照和复用计数 |
| 安装 pytest 首次失败 | 沙箱阻止包镜像网络连接，WinError 10013 | 自动审批通过后仅下载测试依赖；安装日志独立保存，没有发送电池数据 |
| 配置生成脚本第一次报 `ModuleNotFoundError` | 独立 PowerShell 调用没有继承上次的 PYTHONPATH | 补设 `PYTHONPATH=src`；正式入口根据自己的路径导入 src；pytest 配置显式列出 src/tests |
| 17 个新增测试通过、2 个未能启动 | pytest 默认沙箱临时目录不可写 | 指定项目内**新的** `--basetemp`；不能重复指定有历史产物的目录，pytest 会清空该目录 |
| 共享初始缓存入口的集成测试报 WinError 206 | 测试目录名、suite、arm 和源码快照嵌套导致 Windows 路径过长 | arm 输出改为同级短目录，测试使用短临时目录名；新运行仍用唯一 ID，不覆盖旧记录 |
| pytest 可能把返回 ParameterSpace 的辅助函数当测试收集 | 旧 unittest 辅助函数以 test_ 命名并被导入多次 | 给辅助函数设置 `__test__=False`；不把无断言的辅助函数计为通过测试 |
| 旧初始缓存不能用于新评价代码 | 严格缓存校验绑定评价实现源码 SHA-256 | 保持原校验；目标机器用同一 8 个参数重新评价一次，4 组共享并单列成本 |
| 分类器在单一类别、小样本、常量输入/输出时无法提供可靠排序 | 缺少负例或可辨识信息 | 明确回退原 EI；训练 Brier 不能作为校准证明，历史诊断只使用评价之前的前缀 |
| 首次全量测试 78/79 通过，冷启动闭环未得到预期有效点 | GP 不足时总选 Sobol 池首点；每池消耗固定 2 的幂个点，使所选前缀偏向同一区域。原测试也误把“每池消耗多个点”当成“每次只消耗一个点” | 冷启动改用独立固定种子在符合配额的候选中均匀选择；新增可复现与非首点退化回归测试，冷启动集成测试不再假定特定 Sobol 中心必被选中 |

人工问题中，5 次 BO 的第 5 次强制全局探索产生部分倍率标签；D 比 B 多保存了 0.5C 样本，但该标签位于预算末尾，还没有机会影响下一次选点。因此 B/D 曲线相同不代表部分倍率更新无效，必须检查标签何时进入模型以及之后是否还有评价预算。
