# WarmStart实际提示词比较：冷启动、探索、反馈与输出合同

2026-10-14，北京时间。本轮只核对当前文本与已保存的实际请求，没有修改代码/Prompt，没有新API或DFN/GP运行。

比较对象是最新两组24送评上限试验实际使用的warm_start.txt、warm_start_staged.txt和warm_start_select_staged.txt。逐份归档请求的instructions与当前文件正文完全相同，SHA-256匹配；不是仅看文件名推测本轮使用版本。证据位于bo-repair-work/20261014_prompt_text_audit/prompt-context-evidence.json及audit.log。

## 主要判断

两份生成提示词的差别是搜索策略，而不只是措辞多少。原版提供较完整的物理机制提醒并强调较广探索；分阶段版更强调从覆盖较好的历史点附近修正。后者对“完全没有历史数据”的首批生成缺少明确分支，之后又容易让候选围绕尚未完整可行的较差区域集中。这些是文本和轨迹支持的设计问题，但上轮同时改变Prompt、候选池和反馈流程，不能把结果差异全部归因于Prompt。

## 逐项比较

| 项目 | 纯提示词生成warm_start.txt | 分阶段生成warm_start_staged.txt |
|---|---|---|
| 原始长度 | 1578字符 | 1132字符 |
| 最终目标 | 完整四倍率等权RMSE，同时区分可行性和拟合质量 | 最终目标相同，启动阶段先覆盖、之后质量 |
| 物理机制提醒 | 显式写两极库存/面积/扩散时间尺度/电子传导/参数补偿 | 用高倍率扩散、容量/传导联合修正概括，具体物理关系更少 |
| 初次无历史 | 可直接依靠任务、参考参数和物理关系提出候选，但也没有严格分配首批设计 | 主要强调closest_coverage_observations；为空时没有专门写首批设计规则 |
| 探索要求 | 改变不同组合、覆盖未充分探索空间、避免集中 | 不足2完整点时允许集中于有证据邻域，广泛多样性次要 |
| 数值约束表达 | 原范围/孔隙率＋库存系数×体积分数≥required_ah | 显式使用程序计算的derived_necessary_parameter_ranges |
| 真实反馈 | 只在上下文有历史时使用；本轮一次请求没有历史 | 设计上使用真实RMSE、末段残差、覆盖、失败，并按阶段调整 |
| 生成输出 | 六个物理数值的JSON，不输出虚构评分 | 同样输出六个物理数值JSON，不输出虚构评分 |

两份Prompt都允许原范围内的联合参数变化，没有硬编码“只能沿某个方向变化”。分阶段版更保守/集中，是措辞的软引导，不是程序把参数边界缩到了某个邻域。必要库存条件计算的体积分数下界是两组共用物理检查，不能与LLM建议的局部搜索混为一谈。

## 分阶段文本的具体不足

1. **零历史分支不明确。** 文本要求利用整个历史中最接近完整覆盖的8点，但新试验首批该列表为空。应显式区分“无评价”“有失败覆盖反馈但无完整点”“已有完整点”三种状态。当前两个阶段的分界为2完整点，前两种状态被合并，给LLM的首批任务仍偏抽象。
2. **邻域修正没有具体探测结构。** “有物理依据的联合修正”没有规定怎样检验假设、避免反复小幅变化或何时离开覆盖改善停滞的邻域。仅说优先覆盖，并不提供从六维耦合参数到覆盖改善的可靠数值方向；当前没有梯度或因果灵敏度证据，不应假造方向。
3. **多样性从过强走向过弱。** 旧quality版同时强调误差和广泛多样性，在无完整目标时可能分散预算；新staged版允许集中，缓解了这个冲突，却缺少避免锚定较差初始池的退出规则。不同阶段应平衡可行性探索与替代机制检验，而不是把“集中”或“分散”本身当作优点。
4. **操作历史进入通用文本。** “包含此前80候选筛选（若已提供）”没有在本轮注入80点，运行上下文审计证明从零开始；但这段文字是特定历史运行叙述，不是通用方法要求，建议从通用Prompt移除以减少歧义。不能据此声称本轮实际读过旧80点。
5. **选择合同仍需机器校验。** 选择Prompt要求现有合法index，请求JSON也说明零基索引，并非完全没有边界信息；但本轮仍出现24大小池返回[24,25,26,27]。可进一步明确复制当前池index字段、不要使用累计编号，同时继续保留确定性校验。不能承诺再加一句话就能消除此类错误。

## 与本轮实际行为如何对应

纯提示词实际点的归一化两两距离中位数0.6494，反馈组0.2743。反馈组负极体积分数0.68–0.73、负极扩散率1.8e-14–7e-14，分布较窄，且没有完整点。这与“在较差池附近修正而没有充分转移搜索方向”的推断相符，但不是Prompt因果证明。

分阶段提示词写有quality_refinement，但本轮始终0完整点，因此该阶段从未执行。不能把这次0/24称为“RMSE反馈质量阶段无效”；实际只评估了覆盖启动过程。

实际生成有3次，其中前2次真实评价历史为空，第三次收到4条评价；后续选择持续收到8、12、16、20条评价，但没有新的生成调用。**Prompt写着根据反馈提出新点，不代表程序每轮都会让它提出新点。** 未送出生成请求时，改写生成Prompt无法改变当前池中不存在的参数组合，这是机制更新时点的问题。

本轮第一条分阶段生成输出[0.9,0,0,0,0,0]，已被校验拒绝；选择越界也由原合同修复路径处理。只能确认语义约束未被完全遵守，不能从单次异常证明某句Prompt导致非法输出，或用模型名称/随机性忽略它。

## 不是“分阶段系统提示词更长”

分阶段生成系统文本1132字符，比原版1578字符短；选择系统文本657字符。增长主要在运行时context：原版2808字符，反馈组最后一次选择context为32095字符。这些数值按Python Unicode字符计，不是tokens，也未包含外层候选池及其他请求字段。

最后一次选择中，evaluated_observations含20条，failed_candidates含同一批20条，closest_coverage_observations又包含其中8条。同样20个已观察参数在这三个字段中共出现48次，最多重复3次。这是已核对的输入冗余，不能将其理解成48个独立观测。

建议将真实观测只存一份，以ID/标签标记最近、失败及最接近覆盖的记录，保留必要统计而减少重复。压缩可减少输入费用，但没有实验能够证明其必然提高拟合或推理质量。当前两组1对10次API以及不同候选输出量也影响总tokens，不能把全部费用差异归因于重复字段。

## 改进方向与下一步检验边界

若后续批准修改，可保留共同的硬约束/输出合同，显式添加无历史首批设计，区分失败恢复与有完整RMSE时的质量改进，要求候选体现可检验的不同参数补偿假设，并避免把微小数值扰动当作新方向。不要凭未经确认的工况修改物理设置，也不应直接硬编码所有参数最大化。

机制上还需决定新反馈何时触发新候选生成。只由池大小决定补充，可能使后续多轮评价只改变旧池排序；这不是单改Prompt能解决的问题。本轮没有做这些修改。

若要单独比较提示词效果，应固定候选生成数量/调用频率、候选池规则、反馈时点、物理设置和预算，分别换两份生成Prompt，并做多次独立运行。上轮“纯提示词机制对反馈机制”的双组实验不能当作这种Prompt消融，当前也没有新增此类实验。
